# AI 节点：用中文描述，让 AI 在 Subnet 里把网络建出来

## 这是什么

你在 SOP 网络里放一个 Subnet，在里面写一句中文（比如「做一个矮胖的圆柱，顶面压出内凹」），
点一下按钮，AI 就在这个 Subnet **内部**把节点网络搭出来。你可以去干别的，它后台干。
它对结果不满意你就接着提意见，它改。

节点会自己变色、在下方显示状态字，所以你抬眼一看就知道它干完了没有、成没成。

## 为什么不用 MCP

MCP 的方案是把 Houdini 开放成一个服务，让外部的 AI 客户端（Cursor、Claude Code）
去操纵它。这套东西你在调研里已经查清楚了，问题有三个，你当时判断得对：

1. **它在你 Houdini 里开了一个没有沙箱的 shell。** 没有鉴权、没有确认流程，
   任何能访问那个端口的东西都能执行任意代码。这个工具**不监听任何端口**，
   只有向网关发出去的 HTTPS 请求。
2. **会话跑到编辑器里去了。** 对话框、日志、历史全在 Cursor 里，
   而你人是在 Houdini 里干活。这个工具的会话、状态、历史**全在 Houdini 里**，
   而且跟着 `.hip` 走。
3. **AI 抢你的前台。** MCP 是「你请求一步，它做一步」，你得盯着。
   这个工具是「你扔个需求，它后台跑完通知你」。

## 怎么用

### 工具架上只有三个按钮

工具架 `AI` 那一栏（SOP 网络里右键 → `AI` 也是同样三个）：

| 按钮 | 干什么 | 什么时候用 |
|---|---|---|
| **NewAiSub** | 建一个新的 AI 节点 | 每次开工第一步 |
| **AiSubPanel** | 开 AI 面板：对话记录 + 提修改意见 + 回退 | 想改结果、想看它干了什么 |
| **AiSubReload** | 把改过的代码重新装进当前 Houdini | 我改完东西你不想重启 Houdini |

**`NewAiSub` 用的是 Houdini 原生的放置交互**：在 SOP 网络里点它之后，
会有一个虚影跟着鼠标走，你**左键点哪儿它就落在哪儿**；按 **Esc** 可以取消。
如果你当时选中了某个节点，它还会自动接到那个节点后面——和 Houdini 自带的
建节点工具完全一致。

（第一版不是这样的：我直接调 `createNode` 把节点建出来，跳过了整套放置交互，
没有虚影也没法选落点。Houdini 自己的建节点工具都走 `soptoolutils.genericTool`，
它内部会 `pushEventContext('nodegraphselectpos')` 等你点完再把位置塞回来。
现在改成走同一条路。）

> 在 **OBJ 层**用这个按钮时没有虚影——那种情况下得先进一个 geo 再建，
> 落点语义不一样，退回普通创建。在 SOP 网络里用才有。

名字**一律带 `AiSub` 前缀**——光叫 `New Node` / `Panel` / `Reload` 太泛，
离开这个子菜单就不知道是谁家的了。

**曾经有六个，砍掉的理由值得记一笔**（加按钮前先问这三句）：

| 砍掉的 | 为什么 |
|---|---|
| `Build Selected` | 和节点自己的「开始构建」按钮**完全重复** |
| `Dive Into AI Node` | Subnet **双击就能进**，是 Houdini 原生功能，不需要我包一层 |
| `Convert Subnet` | 把已有 Subnet 改造成 AI 节点——低频操作，而且是我自作主张加的 |

`convert` 的功能还在（`houdini_ai.shelf.convert_ui()`），只是不占菜单位置了。
真要用就在 Houdini 的 Python Shell 里：

```python
import houdini_ai.shelf as s; s.convert_ui()
```

### 三步走

1. **放一个 AI 节点**
   在 SOP 网络里右键 → `AI` → `New AI Node`。
   （或者工具架上的 `AI` 那一栏里点；或者用面板右上角的「新建 AI 节点」。）

2. **写描述、点构建**
   选中它，参数面板里找到「描述」，用中文写你要什么。
   然后点「开始构建」。**点完就可以走了**——它在后台线程里跑，不挡你操作。

3. **看状态**
   不用点开任何东西：
   - **节点颜色**：灰=空闲，蓝=构建中，绿=完成，红=失败，橙=已停止
   - **节点下方的字**：直接写着它在干什么 / 结果摘要
   - **Houdini 状态栏**（窗口最底下）：干完或出错时会吱一声，用于你去干别的了的情况

### 面板：两栏

打开 AI 面板（工具架 `AI` → `AiSubPanel`，或任意面板的标签菜单里选 Python Panel → 「AI 节点」）。
它是**给你跟视口/网络编辑器并排摆**设计的——**宽而矮**，所以竖向空间很金贵，
**能一行的绝不用两行**：

```
┌──────────┬───────────────────────────────────────┐
│ ● 塔     │ ● 塔   完成 · 4464 点             ⋯   │
│ ○ 石头   ├───────────┬───────────────────────────┤
│ ● 崖壁   │ 对话      │ 共享记忆 3                │
│          │           │                           │
│          │ 我 做个塔 │ （可编辑的多行文本框）     │
│          │ AI 搭好了…│ 一行一条，直接改/删/加     │
│          │ 我 再高些 │                           │
│          │ AI 加高了…│                           │
│          │           │  3 条         [清空][保存] │
├──────────┼───────────┴───────────────────────────┤
│ + 新建   │ [写修改意见……              ] [发送]    │
└──────────┴───────────────────────────────────────┘
   左：节点              右：内容
```

**几个刻意的取舍：**

- **动作按钮贴着它作用的东西。** 「发送」就在输入框右边（不是飘在右上角），
  「停止」在跑的时候出现在它下面。**「回退」是低频动作，收进了 `⋯` 菜单**——
  它不值得占一个常驻按钮。
- **共享记忆是「内容」，所以它是个标签页**，不是浮层。跟「对话」并列，
  占满整块地方，而且**可以直接编辑**（见下面「共享记忆」那节）。
- **「过程」在标签行的右端**——它是「对话」这一页的显示模式，不是全局动作。
  每一步工具调用（"找节点类型：tube 命中 6 个"）收在它后面，**默认折叠**；
  那些是排查时才看的，平时只会把要读的东西淹掉。
- **「按描述重新构建」不在面板上**——它是节点参数面板里那个按钮的复制品。
  降级进了 `⋯` 菜单（跟当初砍掉工具架上的 `Build Selected` 同一个理由）。
- **网关地址平时不显示**。它占两三行，而唯一有用的时刻是"连不上"的时候——
  所以改成只在配错时才在状态行里冒出来。

### 宽度和层级（前几版这几条都不合格）

早期是**写死的两栏宽度 + 纯文本对话区**，结果在 2000px 宽的面板上：
两边挤成一条、中间一行字横跨半个屏幕、而且**全都是同一号白字没有区分度**。
现在：

**宽度自适应**
- 左边节点列表**按面板宽度成比例**，再夹在上下限之间（越宽越宽，但不会无限撑）
- **右边的文字列有最大宽度上限**（900px）——一行字排到 1800px 是没法读的，
  超出的宽度让给两侧留白，内容居中
- 拖窄到 520px 以下节点列表收进状态行的下拉（安全网，按你"并排摆"的用法用不上）

**视觉层级**
- 说话人「我」是蓝的、「AI」是绿的，都加粗；每条之间留白，行高放开
- 正文颜色**从当前主题读**（不是写死的）——你换浅色主题它跟着换
- 输入框**固定三行高**，写多了内部滚动。**它不会随内容长高**——
  见下面「输入框为什么不再自动长高」。

**多个 AI 节点时**：左边那一栏一行一个，点一下就切过去。你选中某个 AI 节点，
面板也会跟着切（网络编辑器里点节点即可）。

### ★★ 为什么点击输入框曾经完全没反应（这是最绕的一个 bug）

**现象**：点输入框，连光标都不闪，一个字都打不进去。

**先说结论**：这**不是**卡顿，也**不是**控件被禁用、被盖住、或者样式问题。
是**焦点根本没到它身上**。

**怎么找到的**：在活着的 Houdini 里挂事件过滤器，直接听：

```
模拟点击输入框 → MousePress 到达了 viewport   ✅（事件是通的）
               → 输入框从没收到 FocusIn      ❌（焦点没到）
               → win.focusWidget() 变成 AIPanelWidget（面板控件本身）
```

**根因**：面板在 Houdini 里住在 `RE_WindowDrawable`（一个 `QOpenGLWidget`）里面。
**Houdini 的 pane 焦点处理会把焦点交给"面板控件本身"**，而不是里面的输入框。
而面板没有焦点代理，键盘输入就无处可去——表现就是没光标、打不了字。

**为什么之前查不出来**：把同一个面板放进独立浮动窗口，点一下就能拿到焦点
（那里没有 Houdini 的 pane 接管）。所以离屏测试和浮动窗口测试**全都是绿的**。

**修法（两道，互相独立）**：
1. `setFocusProxy(输入框)` —— 焦点一旦落到面板身上，**立刻转给输入框**
2. 输入框 viewport 上挂 `MouseButtonPress` → 强制 `setFocus()`
   （这个事件实测确实到达，所以这条路一定生效）

**顺带发现的**：Houdini 每次重装面板界面都会留一个旧实例（实测一次会话攒了 14 个），
每个都带着一个 800ms 的刷新定时器在扫全场景。现在定时器跟着**显示状态**走
（`showEvent` 起、`hideEvent` 停），僵尸实例的代价归零。

### 输入框为什么不再自动长高

早期版本让输入框**随内容长高**（三行到六行）。它曾经被怀疑是"打字打不进去"
的元凶，加了三层保护也没治好——因为真凶是上面那个焦点问题。

但它确实只是锦上添花，而且是输入这条路上**唯一**会动的控件尺寸。
既然聊天软件都是固定高度 + 内部滚动，就**整个删掉**了：少一个会动的东西，
就少一类说不清的毛病。

### AI 干完之后会自动做三件事

这三件事是它「交活」的一部分，不是你要去要求的：

**一、给容器起个有意义的名字。**
你放下去时它叫 `AI` / `AI1`，干完会变成 `twisted_tower`、`mossy_rock` 这种。
**你自己起过名字的话它绝不动**——它只在名字看着是自动生成的时候才改。

**二、把关键参数提升到容器上——这是最实用的一条。**
它把你**真正会去调**的参数**搬到容器上**，于是你**不用进容器**，选中 AI 节点
就能直接调，改完内部网络立刻跟着变。参数上带中文标签和合理的滑杆范围。

**判据不是"挑几个"，而是"每个功能块都要有自己那套"。**（2026-09-29 改）
你的网络是几件独立的事拼起来的——造型、形变、分布、细节、随机——**每一件都该
有对应的旋钮**，不是整张网络共用一套，也不是随便凑够个数。要的是**精简但有效**：
每个旋钮转一圈画面都看得出变化，不多不少，但覆盖到你可能想调的地方。

它自己的判据是**「把这个旋钮转一圈，画面看得出变了吗？」**——反过来这些**不该**提升：
改了看不出区别的、只有它作者本人才在乎的、内部推导用的中间量、为对齐上游写死的开关、
你永远不该碰的技术选项。

> ★ **它以前会写死"挑 3-6 个"**，那个数字被删掉了——按个数凑出来的旋钮，
> 要么缺、要么是噪声。现在只描述目标，不给个数。

**每次你提修改意见，它都会重新过一遍这份清单。**（2026-09-29 改）
你说「塔身再扭曲一点」，那句话本身就是信号：**扭曲的旋钮在外面吗？**不在就补进来；
已经在外面、但你这次根本没碰的，它会考虑撤掉。以前这一步没有任何要求——
所以才会出现「我提了意见，但它没把该给的旋钮给我」。

**另外**：容器外面**当前有哪几个旋钮**，每一轮都会**直接告诉它**（不用它自己去查）——
否则迭代几轮之后，上一轮的清单会被历史压缩挤掉，它就"忘了"自己把什么搬出去过，
很容易只填一个新的、把原有的全冲掉。

实测效果（`deepseek-flash`，一句「做一个矮胖的石头柱子，表面粗糙一点」+「再高一点，加一些随机扰动」）：

```
容器外面可以直接调的参数：
- 柱子高度：调高调矮（调小就更矮胖）
- 柱子粗细：整体半径缩放
- 整体起伏强度：大尺度轮廓变形量
- 表面粗糙强度：细颗粒起伏幅度
- 粗糙颗粒大小：颗粒尺度，小=细密砂石感
- 随机扰动强度：新增的逐点随机抖动幅度
```

这些名字和说明是它自己写的，直接显示在节点注释里。

**三、自动排版。**
建完会调 Houdini 自己的布局（网络编辑器里「Layout」按钮用的同一个 API）：
主链**从上到下**一条线，分支横向分叉开，汇合点回到中间列。
所以**节点位置不用你管，也不用 AI 管**——它连坐标都拿不到。

### 参数面板长这样

选中 AI 节点，从上到下：

```
描述        ┌──────────────────────────┐
            │ 用中文写你想要什么        │   大文本框（多行）
            │                          │
            └──────────────────────────┘
修改意见    ┌──────────────────────────┐
            │ 对结果不满意就写在这里    │   大文本框（多行）
            │                          │
            └──────────────────────────┘
思考深度    [ 快 ▾ ]

[开始构建]  [发送修改意见]  [停止]          ← 三个按钮排成一行
```

| 参数 | 作用 |
|---|---|
| **描述** | 用中文写你要什么，点「开始构建」 |
| **修改意见** | 对结果不满意就写在这里，点「发送修改意见」——**不用开面板**也能改 |
| **思考深度** | 开工前选：快 / 标准 / 深入 |
| **开始构建** | 按描述构建 / 重做整张网络 |
| **发送修改意见** | 把「修改意见」作为下一轮发给 AI。发送后输入框自动清空 |
| **停止** | 中断正在跑的这一轮 |

**状态、进度、结果摘要、报错全都在节点注释里**（显示在网络编辑器的节点下方），
不占参数面板。节点颜色也跟着状态走。

报错较长时，注释里只放前几行，**完整的那份在 AI 面板里**（那是你点开才看的）。

> 两个文本框是「大」的这件事，Houdini 里没有现成的类型——**它是靠参数标签做的**：
> `editor=1` 开一个文本框，`editorlines=3-10` 定高度，不带 `editorlang` 就是
> 纯文本（带了会按对应语言做语法高亮，中文描述反而会花）。
> 三个按钮排一行靠 `setJoinWithNext(True)`：让本参数和**下一个**参数显示在同一行。
> 这两个都是 Houdini 原生机制，不用自己画界面。

### 思考深度：你自己决定它想多少

**它只管一件事：给它多少思考预算。跑几步、什么时候收工，一概不管。**

| 深度 | 模型思考 | 什么时候用 |
|---|---|---|
| **快** | 关闭 | 需求很明确的小东西，要快要便宜 |
| **标准** | 4096 token 预算 | 默认，够它查清节点和参数 |
| **深入** | 16000 token 预算 | 复杂需求，比如「带细节的科幻控制台」 |

（实测这个网关认 `thinking` 参数：快模式下完全不产生思考块，省 token 也更快。）

**深度是走 API 参数传的，不是写在提示词里让它"自觉"。**
`thinking: {"type": "enabled", "budget_tokens": 4096}` 这种直接交给网关——
那才是真正控制它想多少的地方。提示词里**不提**深度这回事：
能用 API 参数表达的东西，不该用提示词去说（那是层次搞错了，
而且模型"自觉遵守"远不如参数硬控可靠）。

**一轮什么时候结束，由它自己决定。** 它不再调工具了，就是它说「我干完了」。
**没有任何「跑满 N 步就停」的上限**——这一条是 2026-09-29 改的，之前是有的
（快 12 步 / 标准 30 / 深入 80），结果是它第 12 步还在正常干活就被截停，
节点上打出一句「这一轮没收尾：跑了 12 步也没调用 finish」。那句话是**假的**：
网络其实建出来了，是**我**把它掐了，却写得像它失败。

**做完没做完，是事后看容器，不是事前拿数字卡。** 收尾时会真的 cook 一遍容器，
按事实判三种结果之一：

| 容器里 | 状态 | 节点上写什么 |
|---|---|---|
| 有东西、cook 通过 | ✅ 完成 | 结果摘要 + 产出点数 |
| 有东西、cook 报错 | ❌ 失败 | 逐条列出报错 |
| 空 | ❌ 失败 | 说明它没交出任何网络 |

所以它**没调 `finish`** 也一样算完成——我们把 `finish` 那套校验（cook + 收报错）
替它跑一遍再判，不是无脑宣布成功。

**跑的过程里一个字都不会插进去。** 深度选完就交给它，它想多少、查多少、
按什么顺序、什么时候收工，全由它自己决定。

**唯一一次提醒**是在它**打算结束对话**的时候：如果那时候容器里**一个节点都没有**、
而且它一次 `build` 都没提交过（多半是它用文字描述了一遍自己打算怎么建就收工了），
才会提醒它「容器还是空的，请直接调用 build」。容器里已经有东西的话不打扰它——
第二轮你提意见时，它有可能真的判断「现在这样就对了，不用改」。

> **那不设防了吗？** 只剩**一道**，而且它量的是**墙上的钟**，不是步数：
> **一轮超过 `config.json` 里的 `runaway_minutes`（默认 60 分钟）就收手。**
>
> **没有步数上限，也没有任何「原地打转／重复动作」的检测。** 它想反复看同一个
> 东西、想跑一百步，那是它的事——数步数、判打转，都是**我**在替它做决定。
> 曾经有过一道「连着 6 次动作和结果都一模一样就停」的闸，也删了。
> 填 `0` 表示连时间都不管。
>
> 时间到点停下来时**如实说**（「跑满 60 分钟了」），但这一轮已经建出来的东西
> 照样按事实判定——该算完成就算完成，绝不冒充成功，也绝不冒充「没收尾」。

深度是**每个节点各自存的**，可以几个节点用不同深度。默认值在 `config.json`
的 `default_depth` 里改（只影响新建的节点）。

实测差别很大，同一句「做个东西」：

| 深度 | 耗时 | 步数 |
|---|---|---|
| 标准 | 45~100 秒 | 5~11 步 |
| 深入（科幻控制台面板，4464 点） | 210 秒 | 26 步 |

（那两栏步数是**它自己走的**，不是被允许的上限。）

### ★★ 不截断任何内容，也**不发 `max_tokens`**（2026-09-29 改）

原则一句话：**不靠剪短内容来省上下文，只在 API 参数上控制它想多少。**

改之前有三处截断是**实打实的**：

| 截断 | 砍成 | 后果 |
|---|---|---|
| 工具返回（当轮） | 6000 字符 | `polyextrude` 的 96 个参数是 14,393 字符的参数表，被砍到 6000 之后，模型拿到的是一份**残缺 JSON**，而且**没有任何办法**要回剩下那半 |
| 工具返回（历史回放） | 2000 字符 | 同一个返回被砍第二次 |
| `get_node_type` 的参数表 | 120 条 | 排在后面的参数模型**永远查不到**，只能猜，猜错就被拒 |

还有 `get_node_docs` 文档正文 6000、同级节点 60 个、报错 40 条、
菜单合法取值只列前 12 个、共享记忆每轮只给最近 20 条。**全部拆掉了。**

**`max_tokens` 现在一个字段都不发。** 原因是它和「思考深度」直接冲突：
**思考和答案是共享这一个上限的**，而深入档要的思考预算（16000）比旧上限
（8000）还大——**该档承诺的深度物理上够不着**。实测本机网关不传这个字段也认
（它自己的天花板是 65536），换回官方 Anthropic 端点时代码会按域名自动补一个大值。

> 实测把上限压到 8000 时，一轮 11 步里有 3 步撞顶。那 3 步吃掉了 **65% 的时间**
> 和 **67% 的输出 token**；而且**撞顶时工具参数会变成空字典**，模型白干一步。

**撞顶现在会被认出来。** 以前 `stop_reason` 和 `usage` 这两个字段代码**一个都没读**，
所以"输出被砍了"完全不可见。现在：
* `stop_reason == "max_tokens"` → 那一步的工具**不执行**，如实回灌"你被截断了，
  拆小重发"；连续 3 次就收手报失败。
* `usage` 累加记进这一轮，收尾时写在节点细节里（输入/缓存读/输出）——
  **只记录、只展示，绝不据此踩刹车。**

**控制上下文的正当手段剩下两个**，都不是剪短内容：
1. **压缩**：更早的轮次换成"我要求了什么 / 结果是什么"两行（信息还在，换形式）。
2. **让它按需取**：它的历史里已经有完整真相了，不需要的东西它自己不会去查。

**改完实测**（同一句描述、同一档位，各跑一次）：

| | 改前 | 改后 |
|---|---|---|
| 标准档「做个矮胖圆柱，顶面内凹」 | 199 秒 / 11 步 / 输出 35,807 | **307 秒 / 15 步 / 输出 63,638** |
| 深入档「带细节的科幻控制台面板」 | 210 秒 / 26 步 | 365 秒 / 17 步 |
| 输出被截断的步数 | 标准档 11 步里 **3 步撞顶** | **0 次** |
| 缓存命中 | — | **97%**（重发的历史几乎不花钱） |

**⚠️ 它变慢了，而且这是必然的。** 原因不是改动有副作用，而是**以前那几步的思考
被中途砍断了**——你以为「标准档 4096 思考预算」，实际撞到 8000 上限时思考连同答案
一起被切断，那一步白干。现在预算真的用满了（实测每步输出 ≈4,243 token，正好是
4096 思考 + 一点答案）。**要换回速度就把档位调低**，这是你设计的那个旋钮。
（单次样本、描述相同的两次跑，点数从 4096 变成 1057——**点数不是质量指标**，
两次的解法都合理，只是路线不同。要下"质量变好没有"的结论得多跑几次。）

### `.hip` 不会因为对话变长而变大

一轮的完整记录（模型查过的每一张参数表）约 **48 KB**，而它会写进节点 userData，
跟着 `.hip` 走——只增不减，20 轮就是 1 MB。

现在**只留最近两轮的完整记录**，更早的轮次只存那两行摘要。★ 这**不改变模型
看到的任何东西**：更早的轮次本来就会被压成两行，那批完整记录**永远不会被发出去**。
实测：10 轮之后 `.hip` 只涨 87 KB 就**不再长了**（改之前 5 轮就 +247 KB，且持续增长）。

> 中间踩了一个真坑，留个记录：第一版没分清「**正在跑的这一轮**（messages 还是空的）」
> 和「被清掉的旧轮次」，给前者也补了一条摘要 → **本轮的用户消息在请求里出现了两遍**。
> `test_runner.py` 里「中途一个字都没插进去」那条测试当场抓到。区分三种「空」
> 现在是显式写明白的：①正在跑的这一轮 ②存盘时被清掉 ③那轮一条都没攒下就结束了。

### 共享记忆：**变了才注入**（2026-09-29 改）

以前是每轮把最近 20 条塞进**系统提示词**。两个问题：

* 这个节点**自己**写的条目本来就在它自己的对话历史里，每轮重发是纯冗余；
* 系统提示词是**缓存前缀的头部**，放会变的东西，一改就整条前缀失效。

现在按指纹比对（`memory.digest()`），**没变就不发**；真的注入时拼在本轮
**第一条 user 消息**里（追加在末尾，前缀不受影响）。另外记忆**全量给**，
条数界由存储上限 `MAX_NOTES = 40` 定——那是个**明示的**数字，不是在注入时偷偷砍一刀。

> 模型写超长（>500 字）的条目现在是被**拒绝**（告诉它拆成两条），不是被偷偷砍短。
> 但**你在面板编辑框里打多长就存多长**——那个长度闸是给模型设的，不是给你设的。

### 想撤销

在 Houdini 里按 **Ctrl+Z**，AI 这一整轮的操作**一次全部退掉**（不是一格一格退）。
面板上还有「回退到上一轮之前」，能退到任意一轮之前的状态。

## 它是怎么干活的

```
你写的中文
    ↓
AI 先查它自己有多少本事      → list_container（容器里有什么、外面接了哪些几何进来）
    ↓
再查 Houdini 里有哪些节点     → search_node_types（1690 个 SOP 类型，全是真的）
    ↓
再查这些节点的参数            → get_node_type（参数名、合法取值，全是从真实节点上读的）
    ↓
一次提交整张网络             → build（一次交完，不是一个个建）
                            同时给出容器名字 + 要提升到外面的参数清单
    ↓
建完自动做三件事（都是 Python 调 Houdini API，不经过 AI）
    · 接好 Output SOP、挂上 display 标记
    · 调 Houdini 自己的 layoutChildren() 排版（从上到下）
    · 把你的关键参数提升到容器上（ch() 引用）
    ↓
自动 cook、有错自己改        → 报错原样发回给它，它接着修
    ↓
说一句中文总结               → finish（这段字进节点注释，你直接看）
```

### 它能往上看一层，但只能看不能改

除了容器内部，它还能读到**父网络这一层**（工具叫 `list_context`）：上游接的是谁、
下游有谁在消费它的输出、同一个网络里还有哪些节点。**只读，而且只到这一层**，
绝不更深。

**为什么放开这一层**，以及为什么最要紧的是"下游"这一项：

- **上游是谁**它本来查不到。上游的**几何**它其实能量到（容器内把 `__input0__`
  接个 null 再量就行），但"上游是个 `gltf` 扫描件还是一个 `box`"从容器内看不见，
  而那决定了它该用什么思路。
- **★ 下游有谁在消费它的输出 —— 这条是关键。** 你的容器后面如果接着节点，
  AI 大改输出结构（删属性、改点序、换拓扑）会**悄悄搞坏下游**，而且不会报错。
  现在它看得到，就会保守；提示词里也明确让它在这种情况下**在 finish 的说明里
  提醒你一句**「我改了输出的某某结构，下游的 X 可能要看一眼」。
- 同级名单价值中等：知道这个 geo 里已经有什么、有没有别的 AI 节点。

**边界是真的**：`list_context` 只遍历父网络的子节点一次，不做任何递归。
有个测试叫「越不过父网络」，它会在父网络外面放一个特征名字的节点，
断言返回里**根本不出现**那个名字。

**唯一的口子已经堵上**：`build` 允许给节点写 Hscript 表达式，而 Hscript
本来能引用容器外的参数（`ch("/obj/其他/参数")`）。现在表达式走**白名单**——
只允许相对路径、最多往上跳一层（`ch("../参数")`，提升机制用的就是这个）。
绝对路径和 `../..` 会被拒并告诉你原因。

### 共享经验：跨节点，跟着 .hip 走

每个 AI 节点的对话历史是**各自一份**的，所以节点之间原本互相看不见——
同一个 .hip 里第二个 AI 节点不知道第一个建了什么、这个项目有什么坑。

现在多了一份**共享经验**：AI 觉得发现了「别的节点也用得上」的东西，就自己用
`remember` 记一条；每轮开工前自动读给它看。

**记什么、不记什么，判据就一句：别的节点看了这条，能不能少走一次弯路？**
```
✓ 这个项目里 gltf 导入的 uv 是 3 分量
✓ 用户偏好用 attribwrangle 而不是堆一堆小节点
✓ polyextrude 的 translate 是 3 分量参数，不是单值
✗ 我这次建了个塔（那已经在对话历史里了）
```

**跟着 .hip 文件走**——存在 `/obj` 的 userData 上，官方文档明确这类数据是
"Saved with scene file"。你把文件拷到别的机器，经验还在。
（对照组：`cachedUserData` 才是**不**存的。选哪个是查过文档的，不是猜的。）

**上限 40 条**，满了丢最旧的；单条截到 500 字。没上限的话它迟早变成一堆
没人读的日志，而且每轮都要塞进提示词白烧 token。

**看得到、能编辑**：面板上「共享记忆」那个标签页（`对话` 旁边，标题上带条数）
里就是全部条目，**而且可以直接改**：

- 一行一条。改字、删行、自己加一行，都行。
- 改完点「保存」写进这个 .hip。底部还有「清空」（会二次确认）。
- **一字没动过的行，来源和时间都保得住**——写回时按"这行跟原来哪条一模一样"
  认回去。改过或新写的行来源标成`手动编辑`。
- **你正在打字的时候，面板的自动刷新不会覆盖你**（面板每 800ms 刷一次，
  不设这道闸门的话打到一半的字会被冲掉）。
- 手写的条目一样受**条数上限和长度上限**约束——这些是代码拦的，不是靠 UI。

（早期版本是个右下角的浮层，只能看和清空。用户的原话是「共享记忆好丑啊，
这UI为什么放在右下角啊？」+「它也需要一个打字框，我得可以编辑它呀」。）
（带来源和时间），底部一个「清空」（会二次确认）。**只能看和清空，不能编辑**。

### 三条硬规矩（不是靠提示词求它，是代码拦的）

**一、它改不了 Subnet 外面 —— 这是结构性保证，不是检查出来的。**
描述格式里根本没有「路径」这个概念——节点只用名字引用，而名字只在 Subnet 内部解析。
**它没法表达**「去改外面那个节点」，因为语法里不存在这种说法。
（读是另一回事：它能往上看一层，见上面「它能往上看一层」那节。**写仍然只在容器内。**）

**二、它编不出节点和参数。**
所有节点类型和参数名必须是从你**正在运行的 Houdini** 里查出来的。
它写一个不存在的节点名、一个不存在的参数、一个非法的菜单取值，
会被当场拒绝并把原因告诉它，不会静默失效。

**三、它没有危险能力。**
不能执行任意 Python、不能读写文件、不能调 shell。
（它**能**出一张渲染图给自己看，但那条通道是封死的专用管子：不能指定输出路径、
不能接自己的相机、不能渲序列，只能渲它自己那个容器，而且只能从**六个固定轴向**
里挑一个看。见下一节。）

### 为什么参数名要从真实节点上读

这里踩过一个坑，值得记一笔：Houdini 的类型文档**会说谎**。

`polyextrude` 的类型定义里有个参数叫 `lt`，但实际节点上根本没有这个参数——
Houdini 内部有参数页切换机制，文档里放的是候选页的名字，实例上生效的叫 `translate`
（分量叫 `translatex/y/z`）。而且分量命名没规律：`size` 变成 `sizex/sizey/sizez`，
但 `divrate` 变成 `divrate1/2/3`。

如果照着文档告诉 AI 用 `lt`，它会写一个**永远设不上、又不报错**的参数——
静默失效是最难查的那种 bug。所以这个工具一律**临时建一个真实节点、读出参数、再删掉**，
以实例为准。

### 节点注释：上面是历史，最后一行是实时状态

它在跑的时候，节点下方那段字是 **4 行**：

```
· 查参数：polyextrude
· 看一眼（wireframe）
· 提交网络（5 个节点）
[构建中] ◐ 想：…还要在顶上加一圈垛口（18 秒）
```

* **上面最多 3 行是历史**——它**真干完**的事：看了容器、找了节点、查了参数、
  看了一眼画面、提交了网络。**这里不记"思考中"**，那三行要用来看"它刚才在干嘛"。
* **最后一行是实时状态**。等待模型时显示它**正在想/正在说的最后几十个字**
  （`想：…` / `说：…`），后面挂着**秒数**。

为什么要秒数：只有内容的话，模型沉默的那段时间（还没开始想、或者真卡住了）
界面完全不动，看着就像死了。秒表在涨就说明**它还活着**。
这两条是用户提的需求的原话：「思考中我完全看不出来他在干什么……
不然的话，思考中我都不知道他有没有卡住什么的」。

怎么做到的：请求走 **SSE 流式**（`stream: true`），思考是**逐字**送回来的
（`thinking_delta`），所以能显示尾巴。一秒钟最多重画 2 次注释——流的增量
一秒能来几十个，每个都去写一遍是白费。

**如果网关不支持流式**：会自动退回一次性请求，功能照常，只是看不到过程。
而且它**只试一次**——撞上"不认这个请求"就记住，不会每轮都白撞一次。

**一个仍然存在的限制**：请求的读超时是 300 秒（`config.json` 的 `timeout`）。
网关如果彻底没响应，界面会**停在那一行最多 5 分钟**；而且这时候点「停止」
要等这次读超时结束才生效（工作线程正卡在网络上）。秒表能让你**看出来**
它卡住了（数字一直涨），但没法提前掐断它。

### 它能看画面了（`look`：后台出图）

在此之前它只能"跑通了、272 个点、包围盒 3.4×3.4×8"——**形状对不对它不知道**。
现在它多了一个 `look` 工具：把容器渲成一张图，图直接进它的上下文。

**它不会打断你。** 这一条是设计的第一约束，做法是不去碰视口：

| 你可能担心的 | 实际做法 |
|---|---|
| 会不会弹窗 | 不建窗口。用 `opengl` ROP 离屏渲染，全程没有视口对象 |
| 会不会动你的视口 | 不会。不创建、不切换、不读取用户的任何视口 |
| 会不会抢焦点 | 不会。没有 UI 对象被创建，"后台"是字面意义上的后台 |

（第一版方案是建一个浮动视口再截屏——那条路我不敢保证不闪窗、不抢焦点，
所以整个推翻了。现在的路子一次渲染都不需要图形界面。）

**取景是自动的，但视角必须由它指定。**（2026-09-29 改：以前视角是写死的四分之三
视角，用户要求改成强制枚举——「在我们自动确认中心以及距离之后，它应该以什么角度
去看……这个接口应该强制需要一个视角的输入」）

```
+z 前视   -z 后视   +x 右视   -x 左视   +y 俯视   -y 仰视
six 六视图：六个方向排成 3×2 一张图
```

**中心、距离、取景仍然全自动**（算包围盒 → 按 FOV 算距离），它只需要选方向。
**六视图是"一张图里画六个角度"**，不是渲六次：把几何复制六份、各自转到对着相机、
排成 3×2，**只渲一次**——那道"一个会话只出一张图"的保命闸一个字没动。

> 「三视图」被否掉过一次：三视图每根轴只给一面（正/右/俯），**背面看不到**。
> 所以是六视图。

> ★ 相机朝向是**直接写死旋转角**的，不再用 `lookatpath`。两个原因：
> ① `lookatpath` 在视线平行于 Y 轴时**退化**，而俯视/仰视正好是这个方向；
> ② 设了 `lookatpath` 之后 `worldTransform()` 仍只反映 `r`，**没法验证朝向**。
> 六个轴全是 90° 的倍数，写死之后可以**不渲染就读矩阵验证**（测试里逐轴断言，
> 还带一条右手正交断言——行列搞反时它立刻炸）。

**渲染预设**（模型自己在 `look(preset=...)` 里选）：

| 预设 | 用途 |
|---|---|
| `shaded`（默认） | 带光影，看整体形状 |
| `flat` | 无光影纯色，看剪影和穿插关系 |
| `wireframe` | 线框，看拓扑、段数、布线 |
| `wireframe_ghost` | 线框幽灵 |
| `hidden_line` | 隐藏线 |
| `shaded_wire` | 光影 + 线框 |

**还能看属性分布**：`look(attribute="height")` 会把该属性烘成颜色（`Cd`）渲出来，
用来 debug"密度到底堆在哪""高度场长得对不对"。三条校验，缺一不可：

1. **语法**——属性名会被**拼进 VEX 源码**，所以先用正则卡死合法标识符。
   中文名、带连字符的、`x; __import__('os')` 这类一律被拒。
2. **真实存在**——枚举几何上真实的属性名比对，编的名字会被拒（还会列出现有的当参照）。
3. **单值**——多分量属性（`N`/`v`/`P`）被拒，见「已知的限制」里的说明。

提示词里**只告诉它有这个能力，不说"什么时候该看"**——那是它的判断，不是规则。

**★ 一条你现在就该知道的限制**：实测 `opengl` ROP 在**同一个进程里渲第二次会崩**
（`IlmThread::ThreadPool::setThreadProvider`，所有输出格式都一样）。
所以默认**一个 Houdini 会话只出一次图**，第二次会被拦下并说明原因，而不是冒险把你的
Houdini 搞崩。这在无界面环境里是我的实测结论，**但我没法验证 GUI 里的真实行为**
（Houdini 用户日常就在渲 OpenGL 序列，所以这很可能是 hython 特有的）。
你在 GUI 里试过没问题的话，把 `config.json` 的 `screenshot_allow_repeat` 设成 `true` 就放开了。

成本：一张图默认 800×600，几百到一两千 token。**没有每轮张数上限**——
理由和思考深度一样，用限制去防模型乱用是把问题放错了地方。

> ★★ **2026-09-29 修了一个一直都在的 bug**：`opengl` ROP 的 `res` 参数要生效，
> **必须先打开 `tres`（"Override Camera Resolution"，默认是关的）**。关着的时候
> ROP 用的是**相机自己的**分辨率，而新建相机的默认是 1280×720。
> 也就是说在此之前 `config.json` 的 `screenshot_size` 是个**死旋钮**——
> 每张图都是 1280×720，比文档写的贵约 1.9 倍。现在测试里有一条断言
> **渲出来的 PNG 尺寸真的等于配置值**（以前只断言"图不是空的"，所以一直没发现）。
>
> 六视图的画幅是**像素预算封顶、比例跟着内容走**：总像素 = 单张的 3 倍
> （可预测的成本上界），宽高比按六份拼完的实际形状反推。一张图六个角度，
> 每格约是单张的一半像素——这个折扣是值得的。

### ★ 命令桥：不用你点，我直接把重载推进去

上面那张表说的是**你**怎么让改动生效。但更常见的情况是：**我**改完了，
本该由我负责让它生效，不该让你去点按钮。

所以有一个**命令桥**：Claude Code 那边可以把一小段 Python 直接送进**正在运行的**
Houdini 里执行，结果还能拿回来。你什么都不用做。

```bash
# 看有哪些 Houdini 开着
bash scripts/hcmd.sh --list

# 推一条命令（heredoc 管道最省事，不怕引号）
printf '%s\n' \
  'import houdini_ai.reload as r' \
  'ok, msgs = r.reload_all(verbose=False)' \
  'print("重载成功:", ok)' | bash scripts/hcmd.sh

# 或者把代码写成文件再投
bash scripts/hcmd.sh -f mycmd.py
```

**它不监听任何端口。** 走的是一个本地文件夹：

```
~/.houdini-ai-bridge/
  instances/<pid>.json    每个活着的 Houdini 一份心跳
  queue/<pid>__<req>.py   投递的命令（跑完就删）
  queue/<pid>__<req>.out  执行结果
```

Houdini 那边有个守护线程每 0.25 秒扫一次，捡到就用主线程执行。
客户端是纯 bash——连 Python 都不用起。

> **为什么不用 Houdini 自带的 `hrpyc`？** 它一行就能开远程 Python，很方便。
> 但 `hrpyc.start_server()` **绑的是 `0.0.0.0`**，而且函数签名里根本没有 host
> 参数（`--host` 的默认值就是 `0.0.0.0`）。那等于把你 Houdini 里的 Python
> 执行权开放给整个局域网，还没有鉴权。你自己在调研里就把「绑 0.0.0.0」
> 当成避开某个工具的理由，我不该在自己做的工具里犯同样的错。

桥由 `pythonrc.py` 在 Houdini 启动时自动拉起，所以**你不需要做任何事**。
不想要它的话：删掉 pref 目录里的 `pythonrc.py`，或者用
`install.py --uninstall` 一起卸掉。

**手动方式**：Houdini 自带 Python Shell（任意面板 → 右键标签 → **Python Shell**，
或者 New Pane Tab Type → Python Shell），粘这一行：

```python
import sys; sys.path.insert(0, r"C:/Users/32967/Documents/Documents/Godot/.tools/houdini-ai"); import houdini_ai.reload as r; r.reload_all(verbose=True)
```

（`houdini_ai.reload.paste_hint()` 会把这行原样给你，路径自动填对。）

**一个安全阀**：有任务正在跑的时候会**拒绝重载**——重载会换掉 `runner` 模块里的对象，
那个正在跑的工作线程手里还攥着旧模块的东西，重载会让它的状态写不回去。
等它跑完，或者 `reload_all(force=True)` 硬来（不推荐）。

> **两条关于重载本身的事实**（都是踩出来的）：
> * **`importlib.reload` 不会删掉已经消失的名字。** 它是**在同一个字典里重新执行**
>   模块体，所以删掉一个常量之后，跑着的 Houdini 里那个名字**还在**——
>   `hasattr(runner, "REPEAT_STOP")` 依然为真，看起来像改动没生效。
>   现在重载会扫一遍源码、把「源码里已经没有」的名字清掉，并在返回里说一声
>   （「清掉了 runner 里已经删掉的旧名字：…」）。读不到源码或有 `import *` 时
>   宁可不删——误删活名字比留个幽灵名字糟得多。
> * **改 `reload.py` 自己要推两次**：`reload_all` 是在**内存里那份旧代码**的循环里
>   跑的，第一次推只把新代码装进去，**第二次推才真的按新逻辑跑**。

### 三个 XML 相关的坑（都踩过）

**一、`.pypanel` 是 XML，不是 Python 文件。** 我第一版按纯 Python 写，Houdini 直接报
`Could not load ...: Start tag expected, '<' not found`。而且界面类**直接就是 QWidget**，
配一个 `onCreateInterface()` 返回它——不是 `hou.PythonPanelInterface` 子类。

**二、`.shelf` / `.pypanel` 的 XML 属性值只能是 ASCII。** 实测
`label="新建 AI 节点"` → `" AI "`，用 `&#26032;` 数字字符引用**也一样被吃**
（它们不是真正的 XML 解析器）。所以文件里写英文，装进会话之后用 `setLabel()` 改成中文。

**三、★ 这个最阴：给工具架打中文标签会把 `.shelf` 文件写坏。**
实测：一旦对 `Tool` 调 `setLabel()`，**Houdini 会立刻把它加载的那个 `.shelf`
文件整个写回磁盘**，而且中文写成双重编码的乱码——文件里出现
`label="æ°å»º AI èç¹"`。下次启动读到的就是乱码，**比英文标签还糟**，
而且文件永久偏离模板（`--check` 会一直报"内容不同"）。

所以工具架的名字**一律用英文**（也正好是你要的）。这条有专门的记录性测试
（`test_deploy.py`），它断言这个陷阱**仍然存在**——哪天 Houdini 修了，
测试会变红，那时可以重新考虑中文标签。

## 出问题了怎么办

**工具架 / 面板没出现**
工具架和面板**只在 Houdini 启动时扫描**，装完必须重启 Houdini。
重启后还没有，跑 `hython scripts/install.py --check` 看文件在不在、内容对不对。

**状态显示「网关没配好」**
它按这个顺序找配置：环境变量 → `~/.claude/settings.json` 的 `env` 段 → `.tools/houdini-ai/config.json`。
你 Claude Code 用的就是 DeepSeek 的 Anthropic 兼容端点，正常情况下会被自动捡起来。
想换模型或换成官方 Anthropic，改 `config.json` 即可（协议一样，代码不用动）。

**状态显示「工具参数不是合法 JSON」**（2026-09-29 修）
模型那一步的工具调用**参数没拼完整**（最常见的原因是输出写到一半被长度上限截断了），
于是那一步**不能执行**——参数很可能是空的，拿去执行轻则被拒、重则干出莫名其妙的事。

以前这里是**整轮直接结束**，看着就像它"卡死/放弃了"。现在改成：

1. **不执行**那一步；
2. 回灌一句「参数没拼成合法 JSON / 被截断了，请把这一步拆小重发」；
3. **继续跑**——这是模型自己能改的事，不该让整轮死掉；
4. 连着 3 步都不可用才收手，并且**如实说明是「连续 N 步输出不可用」**，不冒充"做完了"。

> 顺带留了**可诊断的证据**：出问题时这一轮的记录里会存下那段参数的**长度、开头、
> 结尾、解析器的原话、以及 `stop_reason`**。以前只报一句"JSON 不合法"，
> 而且**抛异常抛得太早、根本走不到能看见 `stop_reason` 的地方**——真因被自己藏掉了。

**状态显示「失败」，说模型只说不做**
这是真实发生过的一种失败：模型查完参数，就用文字描述它「打算」怎么建，从来不调 `build`。
现在遇到这种情况会催它两次，还是不动就**报失败**——绝不显示绿色的「完成」。
早期版本把「没调工具」当成了做完了，界面显示完成而产出是 0 点，那是更坏的一种失败。

**状态显示「跑满 60 分钟了」**
一轮跑了超过 `config.json` 的 `runaway_minutes`（默认 60 分钟）。**正常情况见不到。**
见到说明它真的陷进去了——这时候看节点注释里的历史行，能看出它卡在哪一步；
再让它跑一轮、在「修改意见」里说清要改什么，通常就能走出来。
嫌 60 分钟太长就调小这个数，填 `0` 表示不管时间。

**它建得不对**
先看面板里的过程记录，能看见它每一步查了什么、提交了什么、为什么被拒。
改描述往往比让它自己悟更快——它对你想要的东西没有画面感，你说得越具体越好。

**跑得太久**
点节点上的「停止」或面板上的「停止」。已经建好的东西会留着。
并发数和那一根时间熔断在 `config.json` 里（`max_concurrent` / `runaway_minutes`）。
**没有「单轮步数上限」这个东西了**——一轮跑到哪儿停，由模型自己决定；
唯一的例外是时间跑满 `runaway_minutes`（默认 60 分钟）。

## 已知的限制（诚实清单）

- **整条向量提升不了，只能提升单个分量。** 想要「尺寸」这个参数在外面可调是做不到的
  （Houdini 的 `ParmTuple` 没有 `setExpression`，没有接口把一整条向量指到外面），
  但写分量名可以——`sizex` / `sizey` / `sizez` 各自提升是行的。
  被拒时错误信息里会给出分量名。
- **容器的四个输入只支持第一个**（`__input0__`）。外部几何接进来了它就会用，
  但接多个输入的组合场景还没做。
- **只能往上看一层，而且是只读的。** `list_context` 看得到父网络（上游是谁、
  下游谁在消费你、同级有哪些节点），但看不到更上面，也一个字都改不了。
  这是刻意的：一级已经覆盖了真正影响决策的信息（尤其是"下游有人接着"），
  再往上就变成把整个项目结构喂出去了。
- **共享经验没有分类和检索**，就是一张按时间排的清单，满了丢最旧的。
  刻意没做标签/向量检索那一套——先把"能记能读"跑通，别一上来就上复杂机制。

- **出图默认一个会话只有一张**（`screenshot_allow_repeat`）。原因是实测
  `opengl` ROP 同进程渲第二次会崩，我不能拿你的 Houdini 去赌。**GUI 里的真实行为
  我验证不了**，你试过没事就把它打开。详见上面「它能看画面了」。

- **属性可视化只看单值属性，向量看不了。** `N` / `v` / `P` 这类多分量属性会被
  **明确拒绝**（带一句可操作的办法：在容器里加个 attribwrangle 把要看的那个分量
  写成新属性，再回来看它）。这是刻意的——底层的 VEX 是 `float v = point(...)`，
  向量喂进去会被**静默取 x 分量**：图渲得出来、看着正常、表达的却是错的东西，
  比直接拒绝坏得多。字符串属性、组、拓扑类的东西也看不了。

- **`build` 是整份替换。** 每一轮它重新提交完整网络，所以你在 Subnet 里**手工调的参数
  会被下一轮覆盖**。只想微调的话它会走 `update_parms`（只改值不动结构），
  但大改结构时手工改动留不住。每轮开始前有快照，Ctrl+Z 和「回退到上一轮之前」都能救。

- **工具架和面板的名字是英文的。** 不是偷懒：`.shelf` / `.pypanel` 的 XML
  属性值只能 ASCII（实测 `label="新建 AI 节点"` 变成 `" AI "`），而用
  `setLabel()` 事后改中文又会被 Houdini 把文件写成乱码（见上面第三个坑）。
  **中文界面在节点参数和 AI 面板内部**，那些是 Qt / HOM 渲染的，没有限制。

- **它搭出来的东西需要你调。** 见下一节。

## 关于质量的实话

r/Houdini 版主给过一条判据：「如果你需要 debug 你展示的这个东西，你能做到吗？
如果答案是不能，那就是 vibe coding。」资深 TD 更直接：除非把每一步用途 100% 全描述出来，
LLM 做到那种优化水平的概率是 0%。

**这个工具消除不了这个风险，只是把它压住了**：它只能用真实存在的节点和参数、
建完自动 cook 把报错回灌给它自己修、每轮能整轮撤销、边界硬隔离在 Subnet 内。

实际跑下来的结果（本机实测，模型 `deepseek-flash`）：

| 描述 | 深度 | 结果 |
|---|---|---|
| 做一个矮胖的圆柱，顶面做出向内凹陷的效果 | 标准 | tube → 线性细分 → attribwrangle 压坑 → normal，578 点。它给的细分理由是对的（顶盖是 n 边形、内部没点，不细分压不出弧形坑） |
| 做一个简单的高塔 | 标准 | 4 个 tube + circle + box + copytopoints 做城垛 + merge，8 节点 272 点 |

| 做个矮胖石头柱子，表面粗糙 | 标准 | tube → subdivide → mountain ×2 → normal，2114 点；提升出 `pillar_height`、`pillar_radscale` 等，外面调实测有效 |
| 再高一点，加随机扰动 | 标准 | 保留原结构加 attribnoise，2882 点。它自己猜错两次参数名，拿到近似名提示后改对 |
| 带细节的科幻风格控制台面板 | **深入** | 倒角机身 + Boolean 挖屏幕槽 + copy-to-points 铺 30 颗随机按键 + 24 块格栅 + 4 个阶梯旋钮，**4464 点**，26 步 / 210 秒。提升了 5 个参数，含中文说明 |

**能看到一个规律**：需求越复杂，深度选高的差别越明显。简单需求用「快」就够，
别浪费钱；复杂需求用「标准」它可能还没想清楚就动手了。

所以：**它搭出个像样的底子，你再来调**，不是一次到位。它自己会说清楚哪些参数最值得你调。
如果质量不够，`config.json` 里换个更强的模型是一行的事——协议是 Anthropic Messages API，
换成官方 Anthropic 或网关上别的模型都不用改代码。

## 想改代码

改 `houdini_ai/` 里任意文件，重启 Houdini 就生效（面板改动连重启都不用，重开面板就行）。

测试是纯脚本，用 hython 跑，不需要 pytest：

```bash
$H tests/run_all.py          # 1146 项，全离线，不花钱
```

其中 `test_runner.py` 用**假网关**回放脚本，能完整验证「AI 调工具 → 我们执行 → 结果回灌 →
它改对了」整个循环，包括它犯错被拒然后自己修正的路径。这条路径才是这套东西真正的工作方式，
所以它有专门的测试盯着。想加新场景就往那里加脚本。
