# 动作生成（Houdini 里用 AI 生成角色动作）

## 这东西是什么

在 Houdini 里**打几个关键帧，让 AI 补出中间的动作**；也可以只给一句文字描述让它生成。
底下跑的是 NVIDIA 的 **Kimodo** 模型，出来的是一根 **SOMA 骨架的逐帧动画**。

**能干什么**

- 你摆几个关键姿势 → 自动补出连贯的动作
- 只写文字（"a person walks forward, then looks left"）→ 直接生成一段
- 多段文字 + 时间轴，每段一个描述和时长
- 地面路径约束（画一条线让它沿着走）
- 手脚末端约束（只钉手/脚的位置，身体其余自由）
- 防脚滑 + **关键帧精确命中**（后端编了 C++ 优化模块）

**不能干什么**

- 出来的骨架是 Kimodo 自己的 SOMA 骨架，**不是你的角色**。要套到你自己的角色上，
  还得走 KineFX 的重定向（`Biped Retarget`）。这一版**没做**。
- 每个提示词最长 10 秒；只吃**英文**。
- 视频/图片提取动作 —— 选型查过了（GEM-X），但**这一版没做**。

---

## 用之前

后端已经装好了，不在 Houdini 里，是独立的一份：

```
D:\kimodo-motion\
  ├─ venv\            Python 3.11 + torch(cu130) + Kimodo + 防脚滑C++模块
  ├─ hf\              模型权重缓存（约 17 GB）
  ├─ src\kimodo\      官方源码
  ├─ output\          生成出来的 .npz
  └─ kimodo_runner.py 推理入口（Houdini 当子进程拉它）
```

**它占显存**：`TEXT_ENCODER_DEVICE=cpu` 模式下生成时占 **<3GB**，跑完立刻释放
（用的是一次性子进程，不是常驻服务）。你 12GB 卡上 Houdini 通常占 5GB 左右，所以够用。

## 三步用法

### 1. 打开动作面板，建一个动作节点

动作面板是一个**独立的 Houdini 面板标签**（Python Panel，接口名
`HoudiniMotionGenerate`），可以像视口、网络编辑器那样**单独停靠、拖动、并排摆**。

打开方式：**右键任意面板标签 → New Pane Tab Type → Motion Generate**
（和 Constraint Browser / Recipe Manager 同一组）。
开了之后可以拖出来单独放一栏，做动画时左边视口、下边时间轴。

**懒得找菜单**：AI 面板右上角有个 **「动作面板」** 按钮，点一下直接开在当前 pane 里。

> ★ 实现上必须用 `.pypanel` 里的 `<includeInPaneTabMenu>`。
> 写成 `<includeInToolbarMenu>` 只会进 Python Panel **内部**的工具条，
> **New Pane Tab Type 里根本找不到**（这个坑踩过）。
> 判据看 `$HFS/houdini/python_panels/` 里官方怎么写的。

进去之后点 **「新建动作节点」**。

它会在 `/obj` 下建一个容器，里面有四样东西：

| 节点 | 干什么 |
|---|---|
| `rest_skeleton` | SOMA 的 T-pose 骨架（动作的起点） |
| `pose_rig` | **你在这上面摆姿势**（KineFX Rig Pose） |
| `motion` | 把生成的 NPZ 变成骨架动画 |
| `out` | 输出 |

另外还有一条**蒙皮支链**（`skin_mesh` / `capture_pose` / `capture` / `deform`），
让 Kimodo 自带的身体网格跟着动——见下面「想看身体网格」。

### 2. 摆关键帧

1. 选中 `pose_rig`，在视口里**用 Rig Pose 的方式拖关节**摆姿势
2. 把时间轴拖到你想钉住的那一帧
3. 回面板点 **「全身姿势」** 按钮

面板上会多一条约束，时间轴上多一个黄色菱形。重复这个循环摆完所有关键帧。

**其它几种约束也是同一个手法**（把播放头拉到目标帧 → 摆好/放好 → 点按钮）：

| 按钮 | 意思 | 怎么摆 |
|---|---|---|
| **根路径** | 让它沿一条地面路线走 | 画一条曲线接到 `motion` 节点的**输入 0**（点的世界 XZ 就是路线；点上有整数 `frame` 属性就是稀疏路点，没有就均匀铺开） |
| **全身姿势** | 钉死整个姿势 | 在 `pose_rig` 上摆好再点 |
| **左手 / 右手 / 左脚 / 右脚** | 只钉那个末端，身体其余自由 | 同上，但只关心那只手/脚的位置 |

### 3. 写文字 + 生成

- **单段模式**：就一段描述 + 时长
- **时间轴（多段）模式**：在「文字段」里加多段，每段一句英文 + 一个时长

然后点 **「生成动作」**。跑完视口里就能 scrub 看动画了。

> 文字**必须是英文**，这是 Kimodo 的限制。写具体点：
> 部位、方向、速度、风格都写上（"a person walks forward cautiously" 比 "walk" 好得多）。

## 几个必须知道的点

### ★ 帧率

**Kimodo 固定 30fps，你的场景可能是 24fps。** 面板会按「**时长不变**」自动换算：
30 帧素材在 24fps 场景里铺成 24 帧（都是 1 秒）。

面板上有 **「设为 30fps」** 按钮——想让帧号一一对应就点它。

### ★ 自动原点

Kimodo 要求**角色在第 0 帧站在原点**。你随手画的路径起点通常不在原点，
所以面板上有 **「自动原点」** 按钮：把所有约束整体平移，让**最早的那个根路点**回到 (0,0)。

**画完路径记得点一下。** 不点的话约束可能根本够不着。

### 建议先「预览 JSON」

点 **「预览 JSON」** 会把将要发给后端的东西打到日志里，还有一组校验提示
（时长超 10 秒、约束帧超出总长、某种约束超过 20 帧……）。生成前扫一眼能省很多返工。

### 想看身体网格

Kimodo 自带一个 SOMA77 的身体网格（18056 点）。动作节点建的时候已经把它接好了：

```
skin_mesh ─┐
           ├→ capture ─→ deform ←── motion（动画骨架）
capture_pose ┘
```

**在视口里显示 `deform` 节点就能看到网格跟着动**（默认显示的是骨架 `out`）。

⚠ 这条链**需要 77 关节的 NPZ**（网格是按 77 绑的，靠关节名匹配）。
真实 CLI 输出的就是 77；官方 demo 里那批样例 NPZ 是切片过的 30，配不上。

## 已知限制（诚实清单）

1. **出来的不是你的角色**。要重定向到自己的角色，得另外搭 `Biped Retarget`（没做）。
2. **只吃英文**。
3. **每段最长 10 秒**（模型限制）。
4. **每种约束建议少于 20 个约束帧**（官方建议，超了动作会糊）。
5. **模型本身不保证精确命中约束**——是后处理那步 C++ 优化把它"掰"过去的。
   本机已经编好了那个模块，所以是精确的；但它**会为了命中而轻微改变动作的平滑度**。
6. **首次生成慢**（要加载模型，几十秒到几分钟）。之后每次生成都要重新加载
   ——这是刻意的：跑完立刻把显存还给你，而不是让模型一直占着 3~4GB。
7. **脚部接触**：官方明说"输入端"（约束里指定接触）还没实现。
   但**输出端有**——NPZ 带 `foot_contacts`，会变成骨架上的 `contact` 属性（0/1，
   只有脚上的关节会非 0）。可以用它做脚部锁定、脚步事件之类。

## 排错

| 现象 | 原因 / 怎么办 |
|---|---|
| 生成按钮点了没反应 | 看面板状态栏和日志。校验没过、没选目标节点、后端不在，都会在这里说清楚 |
| 「后端不在」 | 检查 `D:\kimodo-motion\venv\Scripts\python.exe` 在不在 |
| 生成很慢 / 卡住 | 首次要加载 8B 文本编码器。日志里能看到阶段。面板「停止」能真的中断 |
| 出来的动作很糊 | 约束帧太多（>20）或者文字太笼统 |
| 视口里骨架不动 | 检查帧范围是不是被设成了 1-1；面板生成完会自动设帧范围 |
| 网格不变形 | NPZ 是不是 77 关节；`deform` 节点有没有报错（它上面 Ctrl+E 看） |
| 改完代码不生效 | 点工具架的 **AiSubReload**。**新加模块文件**才需要重启 Houdini |
| 骨架朝向不对/歪 | 检查 `rest_skeleton` 和 `capture_pose` 有没有报错 |

## 给后来改代码的人

```
houdini_ai/
  soma_skeleton.py    关节表（★ 自动生成，别手改）
  soma_npz.py → motion_npz.py   NPZ ↔ KineFX 骨架几何、rest/capture 姿势、蒙皮网格
  motion_rig.py       建网络、读姿势（场景→后端）、把 NPZ 落到场景
  motion_session.py   段/约束的数据模型（纯逻辑）
  motion_api.py       payload 组装 + 起后端子进程
  motion_panel.py     面板界面
data/                 从 Kimodo 素材抽出来的 T-pose 偏移与位置
scripts/
  gen_soma_tables.py      从 Kimodo 源码生成关节表
  extract_soma_tpose.py   抽轴向偏移 + T-pose 位置（带轴向直方图自校验）
```

**面板是独立的 PaneTabType**：`deploy/motion_tools.pypanel`（接口
`HoudiniMotionGenerate`），和 AI 面板平级、各自可停靠。**别把它塞回
AI 面板的子标签里**——子标签不是 pane tab，没法跟视口并排摆。
加面板只改 `deploy.PANELS` 那张表；工具架按钮不受影响，仍然是三个。

**三条不能退回去的设计**：

1. **坐标只有一处换算**。场景帧 ↔ 素材帧在 `motion_session` 里；
   KineFX ↔ Kimodo 的旋转在 `motion_npz.from_kinefx_transform` 里。别在别处再换一次。
2. **`transform` 是世界旋转，不是局部**（本机实测过）。要局部用官方的
   `kinefx.rigapi.computePointLocalTransform`。
3. **`tp` 轴向校正是右乘**（`R_global @ tp`），且判据（轴向直方图）
   **只在 T-pose 上有意义**——动画帧上算它会散开，那是正常的。
